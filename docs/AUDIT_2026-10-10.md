# Marketing101 deep audit

**10 October 2026** · Baseline commit: `8e53d745961efae1b2e27ff48db1d311ff841099`.

## Scope and method

Reviewed product workflows, copy generation, UI editing, validation, authentication, SQLite jobs, browser persistence, exports, and the Pages build. Compared official public product documentation and exercised real Chrome workflows on desktop/mobile, in both Pages and authenticated server modes. This is not a benchmark of competitors' private dashboards, pricing, or conversion performance. No Lighthouse/Core Web Vitals score is claimed.

The main finding: the previous toolkit generated useful preparation assets, but it could lose editor work and lacked the audience → objective → measurement structure needed for disciplined marketing.

## Official-platform comparison

| Reference | Documented pattern | Improvement applied here |
| --- | --- | --- |
| [Buffer content planner](https://buffer.com/features/social-media-content-planner) | Organize ideas and content before moving them into a publishing workflow | Search and format/status/language filters; retained editing buffers; progressive draft loading |
| [Mailchimp segmentation](https://mailchimp.com/help/create-and-send-to-a-segment/) | Target a defined audience instead of treating every contact the same | Explicit audience question/problem, approved differentiator, customer questions, and decision-stage briefs |
| [Mailchimp preview/testing](https://mailchimp.com/help/preview-and-test-your-email-campaign/) | Review and test material before sending | Source-revision warnings and re-review after product changes |
| [HubSpot campaigns](https://knowledge.hubspot.com/campaigns/create-campaigns) | Associate assets with campaign details, goals, and budget | Measurable strategy briefs, independent goal snapshots, campaign/date report filters, and target comparison |

These are workflow inspirations. We did not add a contact database, actual audience-segmentation engine, provider publishing, automated attribution, a paid AI model, or a conversion optimizer. Availability of competitors' features by paid plan was not assessed.

## Findings and fixes

| ID / severity | Baseline finding | Resolution |
| --- | --- | --- |
| A1 / P1 | `studioView` saved one editor section, cleared dirty state, and rerendered the other from persisted records, losing unsaved text. | Separate kit/draft buffers survive independent saves and edits typed while a save is pending. |
| A2 / P1 | Delete/rerender operations could discard other pending edits. Filtering had no way to retain hidden draft edits. | Deletion is blocked with pending work; explicit discard is available. Hidden edits remain in buffers and are included when saving draft edits. |
| A3 / P2 | Product changes left old content marked ready. | Product revisions increment; related drafts revert to draft. Older/unknown source notices require re-review. Existing approved campaign snapshots remain unchanged. |
| A4 / P2 | Launch/enquiry/offer openings ignored the variation counter; several formats repeated unchanged. | All objectives and all six formats have three distinct Arabic/English options. The UI shows the index and explicitly cycles through three local variations. |
| A5 / P2 | All manual reports were aggregated, without campaign/date selection or visible data coverage. | Filters scope metrics, rows, and CSV export. Paired-data counts expose missing measurements. Revenue and sales totals are visible. |
| A6 / P2 | Campaigns had a generic objective without a chosen measurement or hypothesis. | Strategy briefs record stage, objective, metric, target, period, budget, and hypothesis. Campaigns freeze validated copies; selected reports can be compared with the target. |
| A7 / P2 | A long horizontal mobile tab strip made destinations difficult to discover. | A synchronized destination selector respects cancelled unsaved-change prompts. |
| A8 / P2 | Hidden private DOM/editor state survived logout; responses could arrive after session changes. Signup mode also persisted after logout. | Session cleanup empties private views and buffers, epoch checks discard stale responses, and logout returns to sign-in mode. |
| A9 / P2 | Password input was silently trimmed. | New versioned hashes preserve exact input. Existing hashes retain legacy login behavior; tests cover both versions and edge spaces. |
| A10 / P3 | Up to 250 content textareas rendered together. | Initially render at most 20 matching cards with explicit load-more, while filters search the full set. |
| A11 / P3 | A new workspace mostly displayed zero counters with little guidance. | Brand → product → goal → reviewed content → campaign → actual-results steps guide preparation. Completion is not a marketing-performance score. |

The baseline editor findings came from static control-flow tracing. Post-fix browser regressions assert the failure scenarios; no separate production before/after benchmark is claimed.

## Marketing interpretation

The strategy form separates audience understanding, product evidence, the intended action, and its measurement. Discover → Evaluate → Take action is planning guidance, not a universal funnel or a promised conversion improvement.

Completeness counts supplied preparation fields. It does not fact-check a differentiator or forecast performance. A target such as 12 leads in 7 days is user-entered and labeled as a target. Later brief edits cannot silently change a campaign's captured goal.

Manual results stay separate from simulated receipts. Ratios use records with both measurements, and coverage shows how many reports contain those pairs. Target comparisons use only selected reports/dates; they do not prove attribution, causality, or statistical significance. Users must enter compatible, non-overlapping observations.

Copy variation now changes all objectives/formats and uses supplied audience questions and differentiators. It does not invent objection answers, discounts, testimonials, scarcity, or measured outcomes. Source facts retain their entered language; the templates are not automatic translation.

## Next priorities / boundaries

1. Pages remains local browser storage without account isolation or execution while closed. Back up important work.
2. Before public multi-user server hosting, add appropriate recovery/MFA/email verification, deployment supervision, backup-restore drills, and proxy-level rate limiting. This audit is not an enterprise-security certification.
3. A real channel needs OAuth, server-only tokens, asynchronous outbox/leases/reconciliation, provider idempotency, real billing reconciliation, and provider-side caps. Do not place network publishing inside the demo's synchronous SQLite transaction.
4. Reliable optimization requires consistent channel/event definitions and consented conversion data. Sparse manual reports must not trigger claims of a winning ad or automatic spending increases.
5. Full interface localization, real media assets, contact segmentation, and validated statistical experiments remain separate phases. No paid service or marketing account was connected by this release.
